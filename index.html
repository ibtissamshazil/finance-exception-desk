Start here

Five minutes. One auditable workflow.

  1. Select AED 3,500 overage, then run a review. Compare INV-182 with PO-81.
  2. Read the explanation, source evidence, structured JSON, and tool trace.
  3. Record a Hold decision with a note. This records a review action only.
  4. Try the duplicate pair, missing approval, and ledger discrepancy examples.
  5. Select Invented amount test or Broken JSON test, then run again. The validator rejects the draft and uses an offline fallback.
  6. Open Audit trail. Verify the hash chain, then export the evidence.

What runs here

Ten synthetic invoices and ten purchase orders feed Python rules. Decimal arithmetic calculates variances. SQLite records every saved review and reviewer decision. Invoice and PO source records remain unchanged.

Offline demo versus live AI

Offline demo produces deterministic, source-based explanations. It makes no model call. Live AI uses the provider configured in the local .env file. The supplied setup uses OpenRouter with openrouter/free. It sends only synthetic case facts. Free-model availability and rate limits apply.

The live model uses a strict schema and approved source sentences. The validator rejects unsupported evidence or wording. This constrained exercise demonstrates orchestration and validation, rather than open-ended financial advice. Credentials stay on the Python server and never enter browser responses or audit exports.

Controls and limits

Every result requires human review, including clean matches. Mark reviewed records a completed review; it does not approve an invoice or payment. Hold and escalate are local teaching decisions. No payment endpoint, banking connection, invoice-edit tool, or approval tool exists.

The audit checks hash linkage and agreement with saved reviews and decisions. An administrator can rewrite or truncate all matching records together; this demo has no external audit anchor. Reviewer names are self-entered. This local demo has no authenticated users or production authorization controls.
